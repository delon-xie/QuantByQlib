# 策略优化执行时间评估与进度监控

## 一、执行时间预估

### 1. 参数组合数量计算

**early_trend 策略参数**：

```python
EARLY_TREND_PARAMS = [
    StrategyParamSpec("max_convergence_days", "int", 20, [10, 30], 2),    # 11个值
    StrategyParamSpec("max_slope", "float", 0.02, [0.01, 0.05], 1),       # 5个值
    StrategyParamSpec("volume_increase_ratio", "float", 1.2, [1.0, 2.0], 3), # 约4个值
    StrategyParamSpec("trend_formation_days", "int", 5, [3, 10], 2),      # 4个值
]

# 总组合数 ≈ 11 × 5 × 4 × 4 = 880 组参数
```

### 2. 各阶段耗时预估

| 阶段 | 进度范围 | 预估耗时 | 说明 |
|------|----------|----------|------|
| 初始化 | 0-10% | 10-30秒 | Qlib初始化、数据加载 |
| 数据获取 | 10-20% | 30-60秒 | yfinance批量下载939支股票 |
| HMM市场状态 | 20-30% | 5-10秒 | SPY数据分析 |
| **网格搜索** | 30-55% | **30-60分钟** | 880组×2-5秒/组 |
| Walk-Forward | 60-75% | 15-30分钟 | 5个窗口验证 |
| 稳健性检验 | 80-100% | 10-20分钟 | 蒙特卡洛+敏感性 |
| **总计** | - | **60-120分钟** | 约1-2小时 |

### 3. 影响因素分析

| 因素 | 影响程度 | 说明 |
|------|----------|------|
| 股票池大小 | 🔴 高 | 939支 vs 20支 → 耗时差异巨大 |
| 参数组合数 | 🔴 高 | 880组 vs 100组 → 8倍差异 |
| Walk-Forward窗口数 | 🟡 中 | 5个窗口 → 每窗口需重新优化 |
| 蒙特卡洛模拟次数 | 🟡 中 | 1000次 → 每次需评估 |
| 策略复杂度 | 🟡 中 | Early Trend 相对简单 |
| 机器配置 | 🟡 中 | CPU/内存影响回测速度 |

### 2. 进度回调机制

```python
def _cb(self, progress_cb, pct: int, msg: str):
    """进度回调"""
    if progress_cb:
        progress_cb(pct, msg)
    logger.info(f"[Controller] {pct}% - {msg}")
```

### 2. 进度提取脚本

```python
# progress_monitor.py
import re
from pathlib import Path

log_dir = Path("/Users/admin/A股交易日记/logs/")
latest_log = sorted(log_dir.glob("*.log"))[-1]

with open(latest_log) as f:
    content = f.read()
    
# 提取进度信息
progress = re.findall(r"\[Controller\] (\d+)% - (.+)", content)
if progress:
    last_pct, last_msg = progress[-1]
    print(f"当前进度: {last_pct}% - {last_msg}")
    
# 提取已完成的参数组合
grid_search = re.findall(r"网格搜索 (\d+)/(\d+)", content)
if grid_search:
    current, total = grid_search[-1]
    print(f"网格搜索: {current}/{total} ({int(current)/int(total)*100:.1f}%)")
```
