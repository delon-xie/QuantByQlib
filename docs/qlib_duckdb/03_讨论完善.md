### 一、 包核心设计概要

**核心目标**：实现一个基于DuckDB的Qlib数据存储后端，替代原有的文件系统(`bin`)，提供更高性能、更好扩展性（多市场、多频率）以及双向数据流（Qlib ↔ DuckDB）支持。

**关键设计决策**：

1. **按市场(`reg`)分库**：为每个市场（如`cn`, `us`, `hk`）创建独立的DuckDB数据库文件（如`cn_data.duckdb`）。
    
2. **按频率(`freq`)分表**：每个频率（如`day`, `5m`, `1h`）在数据库内拥有独立的特征表（`feature_{freq}`）和日历表（`calendar_{freq}`），这是核心设计，优于单表+字段或分区表方案。
    
3. **无缝集成**：通过实现`FeatureStorage`、`CalendarStorage`、`InstrumentStorage`接口，对Qlib上层应用（如`D.features()`, `Dataset`）保持零侵入。
    
4. **完整生命周期支持**：涵盖从Qlib原始数据迁移、增量更新、日常查询到回导至Qlib标准格式的完整数据流。

### 三、 关键设计点与接口使用方式

1. **初始化与配置**
    
    ```
    import qlib
    from qlib_duckdb import DuckDBFeatureProvider
    from qlib_duckdb.config import DuckDBConfig
    
    # 可选：在初始化前进行全局配置
    DuckDBConfig.set_default(db_root_path="./duckdb_dbs", memory_limit='16GB')
    
    # 初始化Qlib，指定DuckDB作为数据提供者
    provider = DuckDBFeatureProvider(reg="cn")  # reg 指定市场，对应数据库文件 cn_data.duckdb
    qlib.init(provider=provider)
    ```
    
2. **核心Storage的透明工作**
    
    - 用户通过`D.features()`等标准Qlib API查询数据时，`DuckDBFeatureStorage`会根据请求中的`freq`参数自动路由到对应的`feature_{freq}`表。
        
    - 日历和标的池查询同样由对应的Storage处理。
